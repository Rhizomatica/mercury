* OFDM decode fires ~200ms before sender
* PTT-OFF, so effective gap at sender is

* effective gap was ~300ms, causing ~50%
* ACK loss on DATAC1 (< 340ms switch). */

* At 900ms: gap=832ms -- 492ms of clear
* air before the DATAC1 preamble. */

◆ arq_protocol_longest_burst_s()

float arq_protocol_longest_burst_s ( void  )

Longest single-burst airtime across the whole mode table, in seconds.

The RX side must be able to hold a burst of ANY mode the peer might send, not just the one currently selected — the peer can change rung between our bursts, and the first frame of the new rung arrives before we know about it. Buffers sized from the active mode are therefore always one step behind.
